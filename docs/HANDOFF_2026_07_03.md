## 4. Recent Bug Fixes (Complete List)

### 4.1 InvoiceExtractor — the FOC carton bug (CLIENT COMPLAINT — 2 July 2026)

**Symptom:** Client reported that payment summary didn't include carton subsidy for FOC (zero-amount) invoices. Row-level display showed correct RM4/RM3 carton amounts, but summary total dropped them.

**Root cause:** An earlier "fix" made `calcSub` return `{carton:0, p1:0, p2:0, total:0}` when `amt <= 0`. Wrong business logic — goods were still delivered so carton subsidy is still owed. Only the % portions should zero out.

**Fix applied:**

```js
function calcSub(amt,groups,p1,p2){
  const c=groups.reduce((s,g)=>s+g.ctn*g.rate,0), r=v=>Math.round(v*100)/100;
  const carton=r(c);
  // FOC / zero-amount invoices: the goods were still physically delivered, so
  // the CARTON subsidy (RM per CTN × qty) is still owed by the supplier. Only
  // the 0.4% and 0.2% percentages zero out — they're calculated on (amt - carton),
  // which would be negative when amt=0. Total = just the carton amount.
  if(!amt || amt <= 0) return {carton, p1:0, p2:0, total:carton};
  const v1=r((amt-c)*p1), v2=r((amt-c-v1)*p2);
  return {carton, p1:v1, p2:v2, total:r(c+v1+v2)};
}
```

**Impact for prior payments:** Every FOC invoice processed before this fix underpaid by `sum(CTN × rate)` for the FOC invoices in the batch. Worth auditing prior payment summaries to make it right with client if necessary.

**Regression test added:** `invoice_tests.mjs` now has a `[calcSub — real client bug (screenshot)]` section that runs the exact 3-invoice scenario from the client's screenshot end-to-end.

### 4.2 InvoiceExtractor — `parseDesc` failed on all litre product codes

**Symptom:** All litre-based Choon Hua items (Borneo Mineral 1.5L, Ice Mountain 1L, etc.) silently failed volume extraction from description.

**Root cause:** Regex `(\d+(?:\.\d+)?)\s*L(?![A-Z])` had a negative lookahead that rejected "L" if followed by an uppercase letter. But Choon Hua codes pack everything together: `1.5LPLBTN1X12`. The "P" after "L" caused the lookahead to fail.

**Fix applied:**

```js
function parseDesc(desc, code){
  const sources = [desc, code].filter(Boolean);
  for(const src of sources){
    const d = String(src).toUpperCase();
    let volume = null;
    const mlMatch = d.match(/(\d+(?:\.\d+)?)\s*ML/);
    // L regex: digits before L, allow letters after (product codes like "1.5LPLBTN").
    // mlMatch is tried first, so this won't accidentally swallow ML units.
    // Requires digit immediately before L (with optional space), avoiding false
    // positives on words like "BOTTLE" where there's no digit before L.
    const lMatch = d.match(/(\d+(?:\.\d+)?)\s*L/);
    if(mlMatch) volume = parseFloat(mlMatch[1]);
    else if(lMatch) volume = parseFloat(lMatch[1]) * 1000;
    let pack = null;
    const pMatch = d.match(/[X×]\s*(\d+)(?!\d)/);
    if(pMatch) pack = parseInt(pMatch[1]);
    if(volume && pack) return {volume, pack};
  }
  return {volume:null, pack:null};
}
```

### 4.3 InvoiceExtractor — `formatVolUnit(1750)` returned "1.8L"

**Symptom:** r1a rate is labeled "1.75L x 12" but 1750ml items displayed as "1.8L". Confusing/inconsistent.

**Fix applied:**

```js
function formatVolUnit(ml){
  if(!ml || ml <= 0) return '';
  if(ml >= 1000){
    const l = ml / 1000;
    // Use just enough decimal places to be exact: 1.0 → "1", 1.5 → "1.5", 1.75 → "1.75".
    // parseFloat strips trailing zeros so 1.50 → "1.5", 1.00 → "1".
    return `${parseFloat(l.toFixed(3))}L`;
  }
  return `${ml}ML`;
}
```

### 4.5 Payroll — EPF calculated with flat percentage instead of Third Schedule

**Symptom:** Simon Ang Teck Hock (RM2,550 wage) showed EPF 332/281 instead of correct 333/282.

**Root cause:** KWSP prohibits using flat percentages for wages under RM20,000. Must use Third Schedule (Jadual Ketiga) banded calculation: round wage UP to nearest RM20 (upper band edge), apply percentage on that, then ceiling round to next ringgit.

**Fix applied:**

```js
function calcEPF(s, a){
  // Defensive guard: invalid/blank/negative wages → zero deductions.
  if (!s || !isFinite(s) || s <= 0) return { employer: 0, employee: 0 };
  // Banding: round wage UP to nearest RM20 (upper edge of band).
  // For wages > RM5,000, no banding — flat percentage on actual wage.
  const banded = s <= 5000 ? Math.ceil(s / 20) * 20 : s;

  if (a >= 60) {
    // Age 60+ legacy rate: 6.5% employer / 5.5% employee.
    // TODO: verify current 2026 KWSP rate for 60+ citizens (likely 4%/0%).
    return {
      employer: Math.ceil(banded * 0.065),
      employee: Math.ceil(banded * 0.055),
    };
  }

  // Under 60: 11% employee / 13% employer (≤5K) or 12% employer (>5K)
  const employerRate = s <= 5000 ? 0.13 : 0.12;
  return {
    employer: Math.ceil(banded * employerRate),
    employee: Math.ceil(banded * 0.11),
  };
}
```

**Simon's verification:** wage 2550 → banded 2560 → 2560×0.13=332.80 → ceil=333 ✓, 2560×0.11=281.60 → ceil=282 ✓.

### 4.8 Payroll — Garbage ICs returned `NaN` age silently

**Symptom:** Typo'd IC like "abcdef" → age = NaN → `NaN >= 60` is false → silently treats as under-60 with no warning.

```js
function getAgeFromIC(ic, refDate) {
  if (!ic || ic.length < 6) return null;
  const c = ic.replace(/-/g, '');
  const yy = parseInt(c.substring(0,2));
  const mm = parseInt(c.substring(2,4)) - 1;
  const dd = parseInt(c.substring(4,6));
  // Defensive: garbage strings (e.g. "abcdef") parse to NaN. Return null so
  // downstream calcs don't silently treat NaN age as under-60.
  if (isNaN(yy) || isNaN(mm) || isNaN(dd)) return null;
  const yr = yy <= 30 ? 2000+yy : 1900+yy, dob = new Date(yr,mm,dd), ref = refDate||new Date();
  let age = ref.getFullYear()-dob.getFullYear(); const m = ref.getMonth()-dob.getMonth();
  if (m<0||(m===0&&ref.getDate()<dob.getDate())) age--; return age;
}
```

## 6. InvoiceExtractor Module — Full Reference

### 6.1 Overview

- **File:** `InvoiceExtractor.jsx` (1949 lines after fixes)
- **Purpose:** Process Choon Hua supplier invoices, extract line items via AI vision, match items to subsidy categories, compute cascading subsidy, produce claim payment summary
- **AI:** Groq (Llama 4 Scout — see section 9)
- **Supported inputs:** PDF (multi-page) or image files
- **Output:** On-screen payment summary + Excel export + A4 print

### 6.2 Subsidy formula (cascading)

For each invoice with `total_amount > 0`:

1. **Carton subsidy** = Σ (CTN × rate) across all category groups
2. **0.4% subsidy** = round((total_amount − carton) × 0.004)
3. **0.2% subsidy** = round((total_amount − carton − 0.4%) × 0.002)
4. **Total subsidy** = carton + 0.4% + 0.2%

For **FOC / zero-amount invoices** (post 4.1 fix):
- Carton subsidy still applies (goods delivered)
- 0.4% and 0.2% both zero out (would be negative on `amt - carton`)
- Total = just the carton amount

### 6.3 Issue detection categories (8 types)

| Kind | Severity | Triggers when |
|---|---|---|
| `invoice_no` | warn | Doesn't match `^IN\d{8}$` pattern |
| `date` | warn | Unparseable as DD/MM/YYYY |
| `duplicate` | error | Same invoice no. as another in batch. Distinguishes true dupe (same date+amount) from AI misread (different date/amount). |
| `unmatched` | warn | Line item couldn't match any subsidy category. Suppressed when `manuallyAssigned=true`. |
| `extraction_conflict` | warn | AI's volume_ml/pack_size disagrees with description string |
| `ctn_mismatch` | error | Extracted CTN sum ≠ declared PRODUCT TOTAL. Only for multi-category invoices. |
| `ai_uncertain` | warn | AI self-flagged fields as unclear in `uncertain_fields[]` |
| `amount_sanity` | error | Total amount is >3x or <0.4x line sum (decimal misread detector) |

### 7.1 EPF (KWSP)

| Wage tier | Employee | Employer |
|---|---|---|
| ≤ RM5,000 (under 60) | 11% via Third Schedule | 13% via Third Schedule |
| > RM5,000 (under 60) | 11% flat | 12% flat |

| Foreign workers | 2% | 2% |

## 13. Business Logic That Must Not Be Broken

### 13.1 FOC invoices still pay carton subsidy

**Rule:** Goods delivered = carton subsidy owed, regardless of invoice amount.

This was the client complaint. Do NOT reintroduce "amt <= 0 → return all zeros". The fix in section 4.1 is correct.

### 13.2 EPF Third Schedule banding

**Rule:** For wages < RM20,000, EPF must be calculated on upper edge of RM20 band, then ceiling-rounded. Flat percentage is NOT compliant per KWSP.

Do NOT "simplify" this to flat percentage rounding.

### 13.3 SOCSO Cat 1 employee = invalidity + Lindung 24 Jam

**Rule:** Since June 2026, employee SOCSO contribution is `b[2] + b[3]` (both mandatory). Don't remove b[3] thinking it's "extra".

### 13.4 Bonus/incentive treatment

**Rule:**
- EPF wage = salary + incentive + bonus
- SOCSO/EIS wage = salary + incentive (bonus EXCLUDED)

### 13.5 EIS age exclusions

**Rule:** Under 18 and age >= 60 are excluded from EIS (both employer and employee contribute 0).

### 13.6 Description-wins for volume matching

**Rule:** In `matchCat`, when AI's volume_ml/pack_size disagrees with what `parseDesc` extracts from the description string, description wins. AI's numeric fields are less reliable than parsing the printed description text.

### 13.7 True duplicate vs AI misread

**Rule:** Same invoice_no + same date + same amount = true dupe (user uploaded same file twice). Same invoice_no + different date OR amount = AI likely misread invoice number on one. Different error messages, different remediation.

### 13.8 Carton mismatch only flagged for multi-category

**Rule:** For single-category invoices, if extracted CTN sum ≠ declared PRODUCT TOTAL, auto-correct silently (the group's ctn is set to declaredTotal). Only flag mismatch for multi-category invoices where user needs to manually verify per-category CTN split.
